# Base & Raids, phase 1 (simulation) — Implementation Plan

> For agentic workers: implement task by task with TDD (failing unit test first, watch it fail, implement, watch it pass). Commit after each task.

**Goal:** the surface base becomes a place to spend ore and crystal between trips: power ratings, a drill whose upgrades open deeper start floors, buildings placed on our land, and raids that arrive at the pod on a schedule and are fought with the same party combat rules.

**Spec:** `docs/superpowers/specs/2026-10-06-base-raids-design.md` (read §0–§7). This plan is phase 1 of §8 "Simulation (Codex)". Phase 1 leaves out: auto-delve policy, build automation, worker-clone states, soul storage. The UI is done separately by Claude; do not build screens. Expose clean functions and events for the UI.

**Architecture:** new modules under `src/sim/base/` (pure TypeScript, deterministic, seeded RNG only via `p.s.rng`). The surface party is `WorldParty` (`src/sim/overworld/worldSim.ts`, built by `newSurface`). A trip down is `newDelve(seed, floor, carry)` (`src/sim/delve/delveSim.ts`), and the shaft trip is wired in `src/app/expedition.ts` (`up()` / `down()`; carry = `src/sim/roam/carry.ts`). The party combat (`src/sim/party/partySim.ts`, `partyCore.ts`, `partyFoeAi.ts`) already runs on the surface through `worldTick`.

## Global constraints

- Files ≤ 400 lines (`npm run lint` runs `scripts/check-file-length.mjs`); TypeScript strict; `npx tsc --noEmit` clean.
- Korean player-facing strings, terse labels, no explanatory sentences.
- Deterministic: same seed, same inputs → same results. No `Math.random` in sim.
- Turn = 1 unit of sim time (UI shows cooldowns in turns).
- Do not push. Commit on your branch with messages ending `Co-Authored-By: Codex <noreply@openai.com>`.
- The surface has no camps or strays any more (`generateWorld(seed, { pod: true })` returns `camps: []`, no spawns). Keep it that way; raiders come only from raids.

## Task 1 — Power rating

**Files:** create `src/sim/base/power.ts`, test `tests/unit/basePower.test.ts`.

- `unitPower(p: RoamParty, u: Unit): number` — from level (`levelOf` in `partyLevel.ts`), gear numbers (`src/sim/delve/gear.ts` stats), trait count/ranks, promoted (advanced class) bonus. A fresh shell clone ≈ 10; a level-8 promoted clone with decent gear ≈ 60–80. Document the formula in a comment.
- `partyPower(p)` = sum over living clones.
- `floorPower(floor: number): number` — recommended power for a floor (monotonic; floor 1 ≈ 15, floor 5 ≈ 60, floor 10 ≈ 140). Calibrate with the existing bot if cheap (`tests/bot/delveBot.bot.ts`); otherwise a documented curve.
- Tests: monotonic in level and floor; promoted > unpromoted at same level; dead clones count 0.

## Task 2 — Drill upgrades and start depth

**Files:** create `src/sim/base/drill.ts`; modify `src/sim/overworld/worldSim.ts` (state), `src/app/expedition.ts` (use the chosen depth), tests `tests/unit/baseDrill.test.ts`.

- State on `WorldParty`: `drillLevel: number` (0 at start).
- Levels open start floors: level 0 → [1]; 1 → [1, 3]; 2 → [1, 3, 5]; 3 → [1, 3, 5, 8]. Costs: L1 = 30 ore; L2 = 60 ore + 5 crystal; L3 = 100 ore + 15 crystal.
- `drillCost(level)`, `canUpgradeDrill(p)`, `upgradeDrill(p): boolean` (spends, emits `{type:'buff', text:'drill'}` into a returned event list or via a function returning events — follow the codebase's GEvent conventions), `startFloors(p): number[]`.
- Expedition: `down(c, floor = 1)` starts the delve at the chosen floor; keep the default 1 so the current UI still works. Export a way for the UI to pass the floor (e.g. `WorldDemo` option `onDrill(c, floor)`); keep backward compatibility.
- Tests: costs spent exactly; cannot upgrade without materials; start floors per level; a delve started at floor 3 really is floor 3.

## Task 3 — Our land and buildings

**Files:** create `src/sim/base/buildings.ts` (defs + placement), state on `WorldParty`, tests `tests/unit/baseBuildings.test.ts`.

- Our land = `p.claimed` cells (already a Uint8Array round the base; see `claim()` in worldSim). Building is allowed only on claimed, walkable, unoccupied cells.
- Defs (spec §4 table), phase 1 subset:
  - `watchtower` 1×1, cost 20 ore, hp 60, shoots raiders within 6 cells (damage 6–9, every 1.5 turns), and claims land radius 4 round it when built.
  - `wall` tile, cost 1 ore, hp 40, blocks movement (tile becomes non-walkable for pathing; raiders attack it when it blocks their path).
  - `palisade` tile, cost 1 ore, hp 25, cover (like existing cover cells), walkable? No — make it low cover that is walkable but gives the cover bonus; read how `cover` works in `partyCore.behindCover` / `WorldParty.cover`.
  - `gate` tile, cost 3 ore, hp 50, walkable for heroes only.
  - `infirmary` 2×2, cost 40 ore + 10 bio, on return from a trip the party is fully healed.
  - `forge` 2×2, cost 40 ore, sacrifice gives +35% instead of +25% (hook into `gear.ts` sacrifice rate).
- `canPlace(p, kind, at)`, `place(p, kind, at): boolean` (spends), `demolish(p, id)` (refund 50%), `buildingsAt` lookup. Buildings stored in `p.buildings: { id, kind, at, hp, maxHp }[]` and reflected in the map tiles so pathing respects them.
- `recommendedLayout(p): { kind, at }[]` — a ring of walls round the pod at radius 4 with two gates (east/west) and two watchtowers, trimmed to what the ore allows.
- Tests: placement rules (off-land refused, occupied refused, cost), walls block `findPath`, gate passable for heroes, infirmary heals on return (via `placeParty` or the expedition path — put the heal in a function the expedition calls, e.g. `onReturn(p)`), forge raises sacrifice rate.

## Task 4 — Raids

**Files:** create `src/sim/base/raids.ts`, `src/sim/base/raidAi.ts` if needed; modify `worldTick` to run them; tests `tests/unit/baseRaids.test.ts`.

- Schedule (spec §5): the raid clock starts at the first drill upgrade or the 4th trip, whichever comes first; then a raid comes on every 2nd return. The return before a raid emits a warning `{type:'buff', text:'raidSoon', amount: size}`. Track `p.trips`, `p.raidClock`, `p.raidsDone` on WorldParty (the expedition increments trips on each return — call a function like `onReturn(p)` from `expedition.ts` `up()` after `placeParty`).
- Size: grows with raids done and deepest floor reached (`p.deepest`, update it from the carry when a party comes up). `raidSize(p)` returns a number comparable to power; the wave is goblins/archers/brutes summing to that size.
- Spawning: raiders appear at walkable cells on the map edge on 1–2 sides, awake, `group` = raid group, and head for the pod (`p.base`). They attack: clones in reach, then buildings in their way (walls/gates), then the pod. The pod has hp (`p.podHp`, max 200) and can be hit like a building.
- Path through walls: raiders path ignoring walls (treat wall tiles as passable at a high cost); when the next step is a wall/gate building, they attack it until it breaks (building removed, tile walkable again).
- Watchtowers fire at the nearest raider in range each 1.5 turns (emit `shoot` + `hit` events like units do so the view can show them).
- Resolution: raid ends when all raiders are dead (emit `{type:'buff', text:'raidWon'}`) or the pod reaches 0 hp (emit `{type:'dead', text:'raidLost'}`). On loss: lose 30% of ore and crystal (rounded down) and 1–2 random buildings; the pod is restored to 50% hp; the run continues.
- Auto-defence (spec §5): `autoDefend(p): { won: boolean; losses }` resolves the raid instantly when defence power (`partyPower` of clones at base + towers 15 each + walls 1 each) ≥ raid size × 1.2; otherwise returns null and the raid is fought live. Phase 1: provide the function and the comparison; the UI decides whether to call it.
- Tests: schedule (first raid trigger both ways, every 2nd return, warning one return before); raiders spawn on the edge and walk toward the pod; a wall in the way gets attacked and broken; towers damage raiders in range; loss applies the exact penalties; auto-defence threshold; determinism (two runs with the same seed give identical event logs).

## Review focus (things tests must cover)

1. A raid while the party is down the shaft: raids only happen on return (never while away) — assert no raid ticks run during a trip.
2. Building placement never seals the pod off completely from the map edge for raiders (they break walls) and never traps the party (gates).
3. Ore/crystal can never go negative (costs, losses).
4. A party that comes up wiped (no clones) during a raid return: the raid still resolves (auto-loss or towers fight) without freezing.
5. Determinism with the seeded RNG.
