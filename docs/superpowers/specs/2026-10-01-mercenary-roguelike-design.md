# PROJ_R 설계서 — 1차 마일스톤: 수직 슬라이스

작성일: 2026-10-01
상태: 승인됨 (섹션별 대화 승인 완료)

## 0. 개요

### 핵심 판타지
"단 한 명의 이름 없는 초보 모험가로 시작해, 모험에서 만난 사람들과 함께 살아남고 성장하면서 나만의 파티를 만들고, 마침내 최고의 용병단을 만든다."

### 네 가지 핵심 재미 (모든 시스템의 필터)
1. 내가 만든 자동 전투 빌드가 작동하는 것을 보는 재미
2. 예상하지 못했던 강력한 파티 조합을 발견하는 재미
3. 평범했던 용병이 베테랑으로 성장하며 애착이 생기는 재미
4. 성격과 인간관계 때문에 예상하지 못한 사건과 이야기가 발생하는 재미

이 넷 중 어느 것도 강화하지 않는 시스템은 추가하지 않는다.

### 프로젝트 목표와 제약
- 출시(Steam 등)를 목표로 한 게임의 기반. 1차는 수직 슬라이스.
- HTML 기반, three.js 그래픽, Vite + TypeScript.
- 코드는 기능·역할별 모듈로 분리, 파일당 300줄 이하.
- 저장소 `jinha1226/PROJ_R`의 `main`에 푸시, GitHub Actions로 테스트 후 GitHub Pages에 배포해 테스트 플레이.
- 기존 RAIDBOUND 코드는 전부 삭제. KayKit 모델(CC0)과 라이선스만 재사용.

### 마일스톤 분해
| 마일스톤 | 범위 |
|---|---|
| **1 (이 문서)** | 전투 코어 + 성격·관계 전투 행동 + 성장 + 짧은 런 1개(지역 1, 노드 12단계, 1→5명) |
| 2 | 용병단 확장: 여러 파티, 자동 탐험 시뮬레이션과 사건 서사 |
| 3 | 지역 추가, 메타 진행(해금), 콘텐츠 확장 |
| 4 | 밸런싱, 아트·사운드 고도화, 출시 준비 |

### 1차 성공 기준
- Pages 주소에서 새 런을 시작해 보스까지 플레이 가능.
- 전투가 자동으로 진행되며, 이동·돌진·회피·방어·시전·연계가 화면에서 구분된다.
- 성격·관계 행동이 실제로 발생하고(테스트로 검증), 화면에서 아이콘·말풍선·연결선으로 알아볼 수 있다.
- 용병이 레벨업·별명·연대기·장비 외형 변화로 성장하는 것이 보인다.
- CI가 lint/타입체크/단위·시뮬레이션 테스트/빌드/E2E를 통과해야만 배포된다.

## 1. 전투 규칙

### 1.1 전장과 진형
- 전장: 24m × 14m 평면 (x: -12~12, y: -7~7). 엄폐물(바위·기둥) 0~3개, 원형 충돌체.
- 아군 배치칸: 3열 × 4행 격자, x ∈ [-10, -5] 영역. 앞쪽(x가 큰 쪽) 열이 전열. 적 배치는 좌우 대칭 영역.
- 각 유닛은 배치 시 `row`(전열/중열/후열)를 기억한다. "후열 호위" 같은 전술이 이를 참조한다.

### 1.2 시뮬레이션
- 고정 틱: 초당 20틱 (`TICK = 0.05s`). 완전 결정론. 모든 난수는 시드 RNG(mulberry32)에서만.
- 시뮬레이션은 three.js/DOM을 import하지 않는다.
- 유닛은 행동 중이 아닐 때 5틱(0.25초)마다 행동을 결정한다.
- 모든 행동은 3단계: **선딜(windup) → 발동(active) → 후딜(recovery)**. 화면은 선딜 동안 예비 동작을 보여준다.
- 큰 공격은 **위험 범위(telegraph)**를 먼저 생성한다(원형 또는 부채꼴, 선딜 동안 차오름). 발동 시점에 범위 안에 있는 대상만 맞는다. 회피 능력/전술이 있는 유닛은 범위 밖으로 구르기를 고려한다.
- 플레이어 입력(후퇴)은 "틱 N의 명령"으로 기록되어 결정론을 유지한다.
- 최대 시간 90초. 90초 이후 양측 **광폭화**(주는 피해 +50%, 10초마다 +25% 누적).

### 1.3 능력치
| 능력치 | 의미 |
|---|---|
| maxHp | 최대 체력 |
| atk | 공격력 |
| def | 방어. 피해 배율 = 100 / (100 + def) |
| atkSpeed | 기본 공격 주기 배율 (1.0 = 기본) |
| range | 기본 공격 사거리(m) |
| moveSpeed | 이동 속도(m/s) |
| dodge | 단일 대상 공격 회피 확률(0~0.5 제한) |
| crit | 치명타 확률, 치명 배율 ×1.5 |

피해 = atk × 스킬 배율 × 100/(100+def) × (치명 시 1.5) × 기타 보정. 최소 1.

### 1.4 자원
- 스킬: 각자 쿨타임.
- **기세(momentum)** 0~100: 피해를 주면 +(준 피해/대상 maxHp × 40), 받으면 +(받은 피해/자신 maxHp × 60). 100이면 궁극기를 사용할 수 있고 사용 시 0.

### 1.5 이동과 교전
- 조향: 목표 추적(seek), 아군 간 분리(separation, 반경 0.9m), 엄폐물 회피.
- 근접 유닛이 적과 1.2m 이내에서 공격을 주고받으면 **교전 상태**. 교전 중 이탈하면 상대에게 기회 공격 1회.
- 원거리 유닛은 "거리 유지" 성향이 있으면 적이 사거리의 40% 안으로 들어올 때 물러나며 사격한다.

### 1.6 어그로
- 적도 같은 유틸리티 AI를 사용. 목표 점수 = 거리, 위협도(도발, 최근 받은 피해), 대상의 낮은 HP를 합산.
- 도발: 일정 시간 위협도 고정 최댓값.

### 1.7 상태 태그 (연계의 뼈대)
| 태그 | 기본 효과 |
|---|---|
| 표식(marked) | 효과 없음. 반응 스킬의 대상 |
| 넘어짐(knockdown) | 행동 불가 1초 |
| 젖음(wet) | 이동 -10% |
| 기절(stun) | 행동 불가 |
| 화상(burn) | 초당 피해 |
| 출혈(bleed) | 이동 시 초당 피해 |
| 둔화(slow) | 이동 -40% |
| 보호막(shield) | 피해 흡수 |
| 도발(taunted) | 도발자만 공격 |

스킬은 태그를 **부여**하거나 태그에 **반응**(추가 피해·추가 효과)한다. 예: "넘어진 적에게 처형 일격 ×2", "젖은 적에게 번개 연쇄".

### 1.8 쓰러짐·구출·사망
- HP 0 → **쓰러짐(downed)**. 쓰러진 유닛은 **생명선** = maxHp의 50%를 갖는다.
- 쓰러진 유닛이 받는 피해는 생명선을 깎는다(적 AI는 쓰러진 대상을 낮은 우선순위로 노리지만, 광역 공격에는 맞는다). 생명선 0 → **사망**(영구).
- **구출**: 아군이 쓰러진 유닛 옆(1m)에 2초간 머무르면 HP 25%로 일어난다. 유닛당 전투 1회.
- 전투 종료 시 쓰러져 있었던 유닛은 부상(4.3절).

### 1.9 승패와 개입
- 승리: 적 전멸. 패배: 아군 전원 쓰러짐/사망, 또는 후퇴 명령.
- 플레이어 개입: 1x/2x/4x, 일시정지(Space), 유닛 클릭 시 의도·근거 표시, 후퇴 버튼.

### 1.10 시뮬레이션 출력
시뮬레이션은 틱마다 **스냅샷**(유닛 위치·HP·상태)과 **이벤트**를 내보낸다.
이벤트 종류: `move_intent, action_start, action_hit, miss, damage, heal, tag_add, tag_remove, telegraph_start, telegraph_fire, dodge_roll, downed, rescued, died, emotion, relation_trigger, combo, bark, battle_end`.
이벤트에는 `reason`(판단 근거 문자열 키)이 포함될 수 있다.

## 2. 직업·스킬·장비

### 2.1 주인공
- 시작: **견습 모험가**(허름한 옷, 녹슨 검). 기본 공격만 있고 능력치는 전사와 도적의 중간.
- 레벨 3 첫 승급 시 랜덤 직업 3개 중 1개 선택.

### 2.2 직업 6종
| 직업 | id | 역할 | 특징 | 주 태그 | 모델 |
|---|---|---|---|---|---|
| 전사 | warrior | 선봉 | 방패, 도발, 막아서기 | 넘어짐 | Knight |
| 광전사 | berserker | 공격수 | 대검·도끼, 돌진, 광역 베기 | 출혈 | Barbarian |
| 도적 | rogue | 유격 | 단검, 측후방 기습, 회피 | 표식 | Rogue |
| 석궁수 | crossbow | 원거리 | 거리 유지, 관통 사격 | 둔화 | Rogue_Hooded |
| 마법사 | mage | 술사 | 원소 마법 | 젖음·화상·번개 | Mage |
| 사제 | priest | 지원 | 치유, 보호막, 정화 | — | Mage(흰 로브) |

### 2.3 스킬 구조
- 슬롯: 기본 공격 + 액티브 2 + 궁극기 1 + 패시브 2.
- 레벨업 시 **3택 1**: 새 스킬 / 기존 스킬 강화 / 패시브.
- 스킬 풀: 직업별 5개 + 공용 6개 = 36개 내외.
- 스킬 데이터는 선언적으로 정의한다: `{ id, kind, cooldown, windup, active, recovery, range, targeting, telegraph?, effects[], reacts[] }`. 효과는 조합 가능한 작은 단위(`damage, heal, addTag, consumeTag, knockback, dash, shield, taunt, summon` 등).
- 태그 부여 스킬과 태그 반응 스킬이 **직업을 넘나들며** 맞물리도록 배치한다.

### 2.4 전술 카드
- 슬롯: 1개, 베테랑부터 2개.
- 10종: 약자 사냥, 후열 호위, 술사 견제, 거리 유지, 표식 추적, 선봉 돌격, 위험 우선 회피, 쓰러진 아군 구출, 엄폐 활용, 리더 목표 따르기.
- 처음엔 기본 4종(약자 사냥, 후열 호위, 거리 유지, 선봉 돌격) 보유, 나머지는 사건·보상으로 획득.
- 전술은 유틸리티 점수의 **가중치 보정**이다(행동 강제가 아님).

### 2.5 장비
- 슬롯: 무기, 방어구, 장신구. 등급: 낡은 → 일반 → 정예 → 명품 → 전설.
- 무기는 직업 내에서 공격 방식을 바꾼다(예: 전사 한손검+방패 = 수비형, 도끼 = 공격형). 직업별 장착 가능 무기 유형이 정해져 있다.
- 상위 장비는 고유 효과를 가진다. 예: "표식된 적 처치 시 쿨타임 초기화", "넘어진 적 공격 시 출혈", "친한 동료 근처에서 방어 +20%".
- 장비는 외형에 반영된다(투구·견갑·망토·방패·무기 모델, 등급별 재질 색과 광택).
- 수직 슬라이스 장비 30종 내외.

### 2.6 제외 (YAGNI)
- 직업 수 시너지 없음(파티 시너지는 관계가 담당). 제작·강화 없음.

## 3. 성격·관계

### 3.1 성격 특성
- 용병당 2개. 풀 12종. 영입 시 1개 공개, 1개는 첫 전투 또는 첫 사건 후 공개.
- 특성은 (a) 전투 유틸리티 가중치, (b) 감정 반응, (c) 관계 성향(궁합)에 영향.

| 특성 | id | 전투 | 감정·관계 |
|---|---|---|---|
| 무모함 | reckless | 돌진 +, 위험 회피 − | 기세 충전 +25% |
| 신중함 | cautious | 위험 범위 회피 +, 첫 행동 0.5초 지연 | 무모함과 −궁합 |
| 보호본능 | protective | 위험한 아군 엄호 + | 겁쟁이·이타적과 +궁합 |
| 겁쟁이 | coward | HP 30% 이하면 후퇴 | 친구 4m 이내면 '용기' |
| 경쟁심 | competitive | 처치 욕심 + | 라이벌 형성 확률 + |
| 복수심 | vengeful | — | 친구가 쓰러지면 가해자에게 '복수' |
| 다혈질 | hotheaded | — | 피격 시 '분노' 확률 + |
| 냉정함 | calm | — | 감정 상태 효과 절반 |
| 영광 추구 | glory | 보스·정예 우선 | 처치 시 기세 +30 |
| 외톨이 | loner | 4m 내 아군 없으면 공격 +15% | 친밀도 증가 ×0.5 |
| 수다쟁이 | chatty | — | 친밀도 증가 ×1.5, 대사 빈도 + |
| 이타적 | altruist | 아군 치유·보호 + | — |

### 3.2 감정 상태 (전투 중, 지속 3~8초)
| 상태 | 효과 | 주 발동 |
|---|---|---|
| 분노 | 공격 +20%, 방어 −20%, 공격적 판단 | 다혈질 피격, 라이벌 쓰러짐 |
| 공포 | 후퇴 | 겁쟁이 저체력 |
| 고양 | 기세 충전 +50% | 연속 처치, 전우 연계 |
| 복수 | 특정 대상 고정, 공격 +25% | 복수심 + 친구 쓰러짐 |
| 결의 | HP 1로 1회 버팀 | 흉터 '생존자', 주인공 위기 시 친구 |
| 용기 | 공포 면역 | 겁쟁이 + 친구 근처 |

### 3.3 관계
쌍마다 `affinity`(-100~100), `rival`(bool), `battlesTogether`(int)를 기록한다.

| 관계 | 조건 | 전투 효과 |
|---|---|---|
| 친구 | affinity ≥ 40 | 친구 HP 30% 이하 시 엄호 행동 점수 대폭 +, 4m 내 방어 +10% |
| 전우 | affinity ≥ 80 그리고 battlesTogether ≥ 10 | 쌍 전용 연계기(직업 조합으로 결정) |
| 라이벌 | rival = true | 4m 내 공속·치명 +10%, 같은 목표 다툼, 라이벌 쓰러지면 분노 |
| 반목 | affinity ≤ −40 | 4m 내 공격 −10%, 서로 치유·엄호 순위 − |
| 사제 | 레벨 차 ≥ 4 그리고 affinity ≥ 30 | 제자 경험치 +25%, 스승은 제자 엄호 + |

전우 연계기 예: 전사+마법사 "방패 뒤 영창", 도적+석궁수 "표식 저격". 직업 조합 15쌍 중 수직 슬라이스는 8쌍 정의, 나머지 조합은 공용 연계기 "합동 공격".

### 3.4 관계 변화
| 계기 | 변화 |
|---|---|
| 함께 싸운 전투 | affinity +2 (특성 배율 적용), battlesTogether +1 |
| 구출 | 구출자↔대상 +20 |
| 엄호 성공 | +5 |
| 처치 다툼(같은 목표를 서로 노려 막타 경쟁 3회 누적) | 라이벌 형성 판정(경쟁심 보유 시 확률 +) |
| 특성 궁합 | 함께 싸운 전투 증가량에 +궁합 ×1.5, −궁합 ×0.5 및 −1 |
| 휴식 노드 대화 | 선택한 쌍 +10~15 |
| 사건 선택지 | ±5~20 |
| 친구·전우 사망 | 남은 쪽 '상실'(다음 3전투 복수 성향) |

### 3.5 플레이어 활용과 가시화
- 관계 화면은 규칙을 문장으로 보여준다("A는 B가 위험하면 엄호한다").
- 전투 준비 시 인접 관계 효과 미리보기.
- 전투 중: 관계 행동 발동 시 머리 위 아이콘(엄호=방패, 라이벌=불꽃, 복수=붉은 해골), 두 유닛 사이 관계색 연결선, 말풍선. 전우 연계기는 0.5초 슬로모션 + 줌.
- 전투 후 "이번 전투의 순간들" 요약.

## 4. 성장·외형

### 4.1 레벨과 등급
- 최대 레벨 10. 필요 경험치: `40 + 30 × (레벨 − 1)`.
- 레벨업: 스킬 3택 1 + 능력치 성장(직업별 기본치 × 0.85~1.15 랜덤 편차, 용병 생성 시 성장 편차 고정).

| 등급 | 레벨 | 혜택 |
|---|---|---|
| 신입 | 1~3 | — |
| 숙련 | 4~6 | 액티브 강화 선택지 등장 |
| 베테랑 | 7~9 | 전술 슬롯 2 |
| 영웅 | 10 | 궁극기 강화 |

### 4.2 연대기
용병별로 의미 있는 순간을 자동 기록: 첫 처치, 쓰러짐과 구출(누가 구했는지), 관계 형성, 보스·정예 처치, 별명 획득, 흉터, 동료의 죽음.

### 4.3 별명
| 별명 | 조건 | 보너스 |
|---|---|---|
| 수호자 | 구출 3회 | 엄호 중 방어 +15% |
| 불사신 | 쓰러졌다 생존 3회 | 생명선 +25% |
| 거인 사냥꾼 | 보스 막타 | 보스·정예에게 피해 +10% |
| 백인참 | 처치 50 | 처치 시 기세 +10 |
| 그림자 | 회피 30회 | 회피 +5% |
| 치유의 손 | 치유량 누적 3000 | 치유 +10% |

표시: `브란 '불사신'`. 별명은 1개(최초 획득 유지, 이후 획득 시 교체 선택).

### 4.4 주인공 이름
"이름 없는 모험가"로 시작. 첫 동료 영입 시 그 동료가 이름을 묻고 플레이어가 입력.

### 4.5 부상·흉터·사망
- 부상: 전투 종료 시 쓰러져 있었다면 2~3전투 동안 전 능력치 −15%, 외형 붕대.
- 흉터: 생명선이 25% 이하까지 깎였다가 생존하면 30% 확률로 영구 흉터 특성. 흉터는 단점+장점(예: 절름발이 = 이동 −10% / 결의 발동 쉬움).
- 사망: 영구. 추모 목록에 연대기와 함께 보존. 친구·전우에게 '상실' 사건.

### 4.6 외형 성장
- 시작: 채도 낮은 허름한 옷, 투구 없음, 낡은 무기.
- 장비에 따라 투구·견갑·망토·방패·무기 모델 부착, 등급별 재질 색·광택 상승.
- 베테랑: 망토. 영웅: 은은한 오라와 문장.
- 용병별 고유 **개인 색**(옷 포인트, 이름표).

## 5. 런 구조

### 5.1 지도
- 지역 1개 "잿빛 변경". 12단계 × 3갈래 노드 지도(인접 갈래로만 연결), 마지막 보스.
- 한 판 30~45분 목표.

### 5.2 노드
| 노드 | 출현 | 내용 |
|---|---|---|
| 전투 | 많음 | 경험치·골드·낮은 확률 장비 |
| 정예 | 4단계 이후 | 강한 적, 정예 이상 장비 확정 |
| 만남 | 2단계 보장, 이후 간헐 | 후보 2~3명 중 영입 |
| 사건 | 간헐 | 텍스트 선택지, 파티 성격에 따라 숨은 선택지·결과 변화 |
| 휴식 | 6단계 전후, 11단계 | 부상 회복 또는 동료 대화 |
| 상점 | 간헐 | 장비 구매·판매, 치료 |
| 보스 | 12단계 | 잿빛 기사 |

1단계는 항상 전투(혼자 싸우는 튜토리얼 성격). 2단계는 만남 보장.

### 5.3 영입 후보 생성
- 이름, 직업, 특성 2(1 공개), 개인 색, 한 줄 배경, 레벨(현재 단계 기준).
- 20% 확률로 기존 동료와 **과거 관계**(친구로 시작 / 반목으로 시작 / 라이벌로 시작).

### 5.4 인원·자원
- 출전 최대 5명, 대기 최대 3명.
- 자원은 **골드**만.

### 5.5 패배·종료
- 전투 패배 → 후퇴: 참전 인원 전원 부상, 골드 30% 손실, 노드 보상 없음. 런 계속.
- 런 실패: 주인공 사망 또는 전원 사망.
- 런 성공: 보스 처치 → 용병단 이름 짓기 → 결과 화면.
- 결과 화면: 파티, 연대기 하이라이트, 사망자. 기록은 명예의 전당(localStorage)에 보존. 메타 해금 없음.

### 5.6 적
- 산적단(모험가 모델 재색칠): 산적 검사, 산적 궁수, 산적 주술사, 산적 두목(정예).
- 언데드(KayKit Skeletons): 해골 병사, 해골 궁수, 해골 마법사, 해골 졸개.
- 보스 "잿빛 기사": 대형 해골 기사. 위험 범위 내려찍기, 직선 돌진, 해골 소환. HP 50%에서 2페이즈(공속 +, 범위 확대).
- 적 능력치는 단계에 따라 성장.

### 5.7 저장
- 노드 진입·종료 시 localStorage 자동 저장(슬롯 1, `version` 필드 포함). 런 시드 표시.

## 6. 화면·연출

### 6.1 화면 흐름
타이틀 → 지도 → 노드(전투 준비 → 전투 → 결과 / 만남 / 사건 / 휴식 / 상점) → 지도 … → 승리 또는 게임오버. 지도에서 용병단 화면 접근.

### 6.2 화면 목록
- 타이틀: 새 런 / 이어하기 / 명예의 전당.
- 지도: 노드 지도, 현재 위치, 골드, 파티 요약.
- 용병단: 카드 목록, 캐릭터 상세(능력치·스킬·장비·특성·관계·연대기), 관계도(인물 노드 + 관계색 선, 선 클릭 시 규칙 문장).
- 전투 준비: 3×4 배치칸 드래그 앤 드롭, 인접 관계 미리보기, 장비·스킬·전술 변경.
- 전투: three.js 캔버스 + HUD.
- 결과: 순간들 요약, 경험치·레벨업 3택, 전리품.
- 만남 / 사건 / 휴식 / 상점 / 게임오버 / 승리.

### 6.3 전투 연출
- 카메라: 직교, 약 55° 내려다보는 약한 쿼터뷰. 아군 좌, 적 우. 전투 범위 자동 추적·부드러운 줌.
- 캐릭터: KayKit 리깅 모델 + 애니메이션(대기, 이동, 공격, 방어, 피격, 구르기, 시전, 쓰러짐) + 코드 기반 돌진 이동·넉백·피격 번쩍임·약한 화면 흔들림.
- 머리 위 HTML 오버레이: 개인 색 이름표, HP·기세 바, 상태·감정 아이콘, 피해 숫자, 말풍선.
- 이펙트: 베기 궤적, 투사체, 치유 빛, 보호막, 위험 범위 데칼, 태그 표시(표식 룬, 젖음 물방울, 화상 불꽃).
- 관계 연출: 아이콘 + 관계색 연결선 + 말풍선, 전우 연계기 슬로모션.
- 의도 표시: 일시정지 중 유닛 클릭 → "리아를 엄호하러 이동 중 (친구 · 보호본능)".
- 전투 기록: 접이식, '관계 행동만 보기' 필터.

### 6.4 기타
- PC 우선(1280×720 이상), 모바일은 깨지지 않는 수준.
- UI 문자열은 `ui/i18n/ko.ts`에 집중.
- 사운드: CC0 효과음 소수 + 음소거. 음악은 제외.
- 배경: KayKit CC0 숲·던전 소품, 따뜻한 방향광 + 그림자.

## 7. 코드 구조·테스트·CI

### 7.1 의존 규칙
- `core` ← `data` ← `sim` ← `app` ← `view`, `ui`. 역방향 import 금지.
- `sim`, `data`, `core`는 three.js·DOM을 import하지 않는다(ESLint `no-restricted-imports` + 경로 규칙).
- 파일당 300줄 이하(CI 스크립트 `scripts/check-file-length.mjs`).

### 7.2 디렉터리
```
src/
  core/      rng, vec2, ids, 이벤트 타입
  data/      classes/ skills/ traits/ tactics/ items/ enemies/ events/ names/ backstories/ combos/
  sim/
    battle/  state, loop, movement, engagement, damage, tags, telegraph, emotions, relations, rescue, outcome
      ai/    utility, considerations/*, intents
    roster/  mercenary, leveling, chronicle, titles, injuries, relationships
    run/     mapgen, nodes, recruit, events, rewards, shop, runState
  app/       main, screens(router), store, save
  view/
    scene/   renderer, camera, lighting, arena
    actors/  assets, actorFactory(모델+장비 부착), animator
    fx/      particles, projectiles, telegraphs, tethers, damageNumbers
    playback/ battlePlayer(이벤트→연출), interpolation
  ui/        screens/*, components/*, i18n/ko.ts
public/assets/ 모델, 소품, 효과음, ART.md(출처·라이선스)
tests/       unit/ sim/ e2e/
```

### 7.3 전투 실행
- 실시간 고정 틱 진행. 프레임마다 속도에 따라 1~4틱 진행, 화면은 직전 두 스냅샷 보간.
- 헤드리스 실행은 같은 루프를 화면 없이 반복(테스트, 마일스톤 2의 자동 탐험).

### 7.4 테스트
- Vitest 단위: 피해 계산, 태그 반응, 관계 기준값, 레벨업, 지도 생성, 저장/불러오기.
- 결정론: 같은 시드·입력 → 같은 이벤트 흐름.
- 밸런스 스모크: 시드 고정 전투 수백 판 헤드리스 실행 → 예외 없음, 대부분 90초 내 종료, 단계별 승률 목표 범위.
- 행동: 친구 위험 시 엄호 이동, 겁쟁이 후퇴, 복수 대상 고정, 라이벌 근처 버프 등 성격·관계 행동이 실제로 발생.
- E2E(Playwright): 로드 → 새 런 → 첫 전투 → 종료, 스크린샷 저장.

### 7.5 CI
- 모든 push/PR: `npm ci` → lint(파일 길이·의존 규칙) → `tsc --noEmit` → Vitest → `vite build` → Playwright → 스크린샷·빌드 산출물 업로드.
- `main` push: 위 단계 통과 시 GitHub Pages 배포(`https://jinha1226.github.io/PROJ_R/`, Vite `base: '/PROJ_R/'`).
- 기존 RAIDBOUND 파일·워크플로 삭제, KayKit 모델·라이선스만 이전.
- 기존 저장소의 모델은 애니메이션이 9개로 잘려 있고 Rogue는 후드 버전뿐이므로, 필요한 모델(Rogue 비후드, Skeletons, 무기·소품)과 애니메이션은 KayKit 공식 저장소의 고정 리비전에서 가져오고 `public/assets/ART.md`에 출처를 기록한다.
